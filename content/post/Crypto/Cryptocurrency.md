# 가상자산과 블록체인 핵심 원리

블록체인과 암호화폐(Cryptocurrency) 시스템을 지탱하는 암호학적 기반과 분산 합의 메커니즘에 대해 살펴봅니다.

## 암호학적 해시 함수 (Cryptographic Hash Function)
해시 함수는 임의의 크기를 가진 데이터를 입력받아 정해진 고정 길이의 출력값(비트코인 기준 256비트)을 다항 시간 내에 계산하는 함수입니다.

암호학적 해시 함수는 일반 해시 함수와 달리 다음 3대 보안 속성을 반드시 만족해야 합니다:
1. **충돌 저항성 (Collision-Free)**
2. **은닉성 (Hiding)**
3. **퍼즐 친화성 (Puzzle-Friendly)**

### 속성 1. 충돌 저항성 (Collision-Free)
- $x \neq y$ 일 때 $H(x) = H(y)$를 만족하는 서로 다른 두 입력쌍을 현실적인 시간 내에 찾아낼 수 없어야 합니다.
- 입력 가능한 공간의 크기가 출력 공간보다 무한히 크므로 수학적 충돌 자체는 반드시 존재하지만, 무작위 대입으로 충돌을 찾을 확률은 천문학적으로 낮아 실질적으로 불가능합니다.
- **Hash as Message Digest**: 충돌을 찾는 것이 불가능에 가까우므로, $H(x) = H(y)$라면 $x = y$라고 확신할 수 있습니다. 이를 통해 전체 대용량 메시지 대신 고정 길이 해시값만 비교하여 데이터 무결성을 검증할 수 있습니다.

### 속성 2. 은닉성 (Hiding)
- 출력값 $H(x)$가 주어졌을 때 원본 입력 $x$를 역산하여 유추할 수 없어야 합니다.
- 높은 최소 엔트로피(High Min-Entropy)를 가진 무작위 난수 $r$을 $x$와 결합(Concatenate)하여 $H(r \parallel x)$ 형태로 해시하면 완벽한 은닉성을 보장할 수 있습니다.
- **Commitment API와 보안 속성**:
  - `(commitment, key) = commit(msg)`: 메시지를 봉인하여 커밋값과 키를 생성합니다 ($H(key \parallel msg), key$).
  - `match = verify(commitment, key, msg)`: 커밋값과 키, 메시지를 검증합니다.
  - 커밋먼트는 봉인을 풀기 전에는 내용을 알 수 없는 은닉성(Hiding)과, 한 번 봉인한 메시지를 다른 메시지로 바꿔치기할 수 없는 결속성(Binding)을 제공합니다.

### 속성 3. 퍼즐 친화성 (Puzzle-Friendly)
- 무작위 난수 $k$가 주어졌을 때, $H(k \parallel x) = y$가 되도록 만드는 $x$를 사전에 계획적으로 찾아낼 수 없어야 합니다.
- 특정 목표값 $y$를 만족하는 입력 $x$를 찾기 위해서는 오직 무차별 대입(Brute-force)만을 수행해야 하며, 이는 비트코인 작업 증명(PoW)의 수학적 기초가 됩니다.

### SHA-256 구조
- 메시지를 512비트 블록 단위로 분할한 후 256비트 초기 벡터(IV)와 함께 압축 함수를 연쇄적으로 수행합니다.
- 마지막 블록이 512비트에 미치지 못할 경우 패딩을 추가하여 길이를 맞춥니다.
- 압축 함수 단계마다 충돌 저항성을 보존하므로 전체 SHA-256 알고리즘 또한 강력한 충돌 저항성을 유지합니다.

## 해시 포인터와 블록체인 자료구조
- 해시 포인터(Hash Pointer)는 특정 데이터가 저장된 메모리 위치(포인터)와 함께 해당 데이터의 암호학적 해시값을 동시에 보관하는 포인터입니다.
- 데이터를 참조하는 것뿐만 아니라 데이터가 임의로 변조되었는지 검증(Tamper-Evident)할 수 있습니다.
- **단방향 연결 리스트 (Block Chain)**:
  - 각 블록은 데이터와 함께 이전 블록에 대한 해시 포인터를 포함합니다 ($H(root) \leftarrow B_1 \leftarrow B_2 \leftarrow B_3$).
  - 중간 블록($B_2$)의 데이터를 변조하면 상위 블록($B_1$)과 루트 해시까지 연쇄적으로 불일치가 발생하므로 위변조가 즉시 감지됩니다.
  - 가장 최초의 시작 블록을 **제네시스 블록 (Genesis Block)**이라 부릅니다.
- **머클 트리 (Merkle Tree)**:
  - 해시 포인터를 이진 트리 형태로 구성한 자료구조입니다.
  - 단말 노드(Leaf)에는 트랜잭션 데이터가 담기고, 부모 노드는 두 자식 노드의 해시 결합값을 가집니다.
  - 임의의 트랜잭션이 블록에 포함되었는지 증명할 때 전체 데이터를 순회할 필요 없이 루트까지의 경로 상에 있는 $O(\log n)$개의 노드(머클 경로)만으로 무결성을 검증할 수 있습니다.

## 전자 서명 (Digital Signature)
- 본인만이 서명을 생성할 수 있고(Sign), 누구나 공개키로 서명의 진위를 검증할 수 있어야(Verify) 합니다.
- 서명과 서명 대상 문서가 불가분하게 결합되어야 합니다.
- 핵심 인터페이스:
  - `(sk, pk) = generateKeys(keysize)`: 비밀키(Secret Key)와 공개키(Public Key) 쌍 생성
  - `sig = sign(sk, message)`: 비밀키로 메시지(또는 메시지의 해시값)에 서명 생성
  - `isValid = verify(pk, message, sig)`: 공개키로 서명의 유효성을 검증
- 비트코인은 타원곡선 디지털 서명 알고리즘인 **ECDSA(secp256k1 표준)**을 채택하고 있습니다.

## 공개키와 주소 (Identity)
- 공개키는 네트워크 참여자를 식별하는 식별자(ID) 역할을 하며, 비밀키는 해당 식별자로 트랜잭션을 승인할 수 있는 권한을 나타냅니다.
- 비트코인에서는 중앙 발급 기관 없이 누구나 로컬에서 무작위 난수를 통해 새로운 키 쌍과 지갑 주소(Address)를 자유롭게 생성할 수 있습니다.
- 탈중앙화된 가명성(Pseudonymity)을 제공하지만, 공개된 트랜잭션 장부의 입출력 관계를 클러스터링 분석하면 특정 개인의 거래 패턴을 추적할 수 있는 한계가 존재합니다.

## 암호화폐와 이중 지불 문제
- 디지털 자산은 복제가 자유롭기 때문에同一한 화폐를 두 번 이상 지불하는 **이중 지불 공격(Double Spending Attack)**을 방지하는 것이 핵심 과제입니다.
- 각 트랜잭션은 이전 트랜잭션의 출력을 소비(Consume)하고 새로운 출력을 생성(Create)하는 체인 구조로 연결되어 거래 이력을 엄격하게 검증합니다.
- 중앙 관리자가 장부를 승인하면 이중 지불을 쉽게 막을 수 있지만, 이는 중앙 집중화(Centralization) 문제를 유발하므로 P2P 분산 합의가 필수적입니다.

## 탈중앙화 분산 합의 (Decentralization & Consensus)

### 분산 합의 (Distributed Consensus)
- 수많은 분산 노드가 네트워크 지연과 장애, 악의적인 노드의 공격이 존재하는 상황에서도 단 하나의 정당한 거래 장부(Block Chain)에 합의해야 합니다.
- 전통적인 비잔틴 장군 문제(Byzantine Generals Problem) 해결책(Paxos, PBFT 등)은 노드의 신원과 수가 고정되어 있어야 하는 제약이 있었습니다.
- **암호화폐의 분산 합의 (Public Consensus)**: 비트코인은 비잔틴 장애 허용을 오픈 P2P 네트워크 환경으로 확장하여 블록 단위로 합의를 형성합니다.
- **신원 없는 분산 합의 (Consensus Without Identity)**:
  - 누구나 자유롭게 참여할 수 있는 무허가(Permissionless) 네트워크에서는 노드 수만 늘려 투표권을 독점하는 시빌 공격(Sybil Attack)에 취약합니다.
  - 비트코인은 IP나 노드 개수 대신 연산 자원(Computing Power)의 비율에 비례하여 합의 권한을 분배하는 방식을 취합니다.
- **정직한 노드 유도 (Honesty & Incentive)**:
  - 정직하게 유효한 블록을 생성한 채굴자에게만 블록 보상(Block Reward)과 트랜잭션 수수료(Transaction Fee)를 지급하는 경제적 인센티브 알고리즘을 결합하여 자발적으로 규칙을 준수하도록 유도합니다.

### 작업 증명 (Proof of Work)
- 다음 블록을 생성할 권한을 얻기 위해 암호학적 해시 퍼즐을 가장 먼저 해결하는 경쟁 방식입니다.
- 채굴자는 블록 헤더에 임의의 값(Nonce)을 변경해가며 전체 헤더의 해시값이 목표값(Target)보다 작아지는 조건을 만족해야 합니다:
  $$\text{SHA-256}(\text{SHA-256}(\text{BlockHeader})) < \text{Target}$$
- **Proof of Work 핵심 속성**:
  1. **연산의 난이도 (Difficult to compute)**: 목표 해시를 찾기 위해 천문학적인 연산 횟수가 필요하며, 이는 무작위 확률 과정(Poisson Process)을 따릅니다.
  2. **가변적 난이도 조절 (Parameterizable cost)**: 전 세계 채굴 해시파워의 증감에 관계없이 블록 생성 주기가 평균 10분으로 수렴하도록 매 2016블록(약 2주)마다 난이도를 자동 재조정합니다.
  3. **검증의 용이성 (Trivial to verify)**: 해시를 찾는 데는 막대한 에너지가 소모되지만, 다른 노드들이 해당 블록이 유효한지 검증하는 데는 단 한 번의 해시 연산($O(1)$)으로 충분합니다.
