## GCC 컴파일 동작 과정

GCC(GNU Compiler Collection)는 C 및 C++ 소스 코드를 기계어로 번역하여 실행 파일로 만들어 주는 컴파일러 도구 모음이다. 단순하게 `gcc main.c` 명령을 입력하면 즉시 실행 파일인 `a.out`이 생성되지만, 내부적으로는 아래의 4단계를 순차적으로 거친다.

1. **전처리 (Preprocessing)**:
   - `#include`, `#define` 등 전처리기 지시자를 해석하여 소스 코드(`.c`)를 전처리된 C 소스 코드(`.i`)로 확장한다.
   - 명령어: `gcc -E main.c -o a.i`

2. **컴파일 (Compilation)**:
   - 전처리된 소스(`.i`)를 각 아키텍처에 맞는 어셈블리 언어(`.s`)로 변환한다.
   - 명령어: `gcc -S a.i -o a.s`

3. **어셈블 (Assembly)**:
   - 어셈블리 코드(`.s`)를 기계어 목적 파일인 오브젝트 파일(`.o`)로 변환한다.
   - 명령어: `gcc -c a.s -o a.o`
   - `file a.o` 명령으로 파일 속성을 확인하면 `LSB relocatable`로 표시된다. 이는 다른 오브젝트 파일과 결합할 수 있는 재배치 가능 파일이며, 직접 실행할 수는 없는 상태이다.

4. **링킹 (Linking)**:
   - 생성된 오브젝트 파일과 외부 라이브러리, C 런타임 시작 코드(crt)를 결합하여 최종 실행 파일을 생성한다.
   - 명령어: `gcc a.o -o out`
   - `file out` 명령으로 확인하면 `LSB executable`로 표기되어 직접 실행이 가능하다.

- **전체 중간 생성물 보존 옵션**:
  ```bash
  gcc -v --save-temps -o out main.c
  ```
  위 명령을 수행하면 `.i`, `.s`, `.o` 중간 파일들을 모두 보존하면서 각 단계별 상세 로그를 터미널에 출력한다.

- **기타 링킹 및 보안 옵션**:
  - `ldd <실행파일>`: 실행 파일이 의존하는 공유 라이브러리 목록을 확인한다.
  - `-no-pie`: ASLR(Address Space Layout Randomization)을 지원하는 시스템에서 위치 독립 실행 파일(PIE) 형태가 아닌 고정 주소 바이너리로 빌드한다.

## 라이브러리 개념 및 빌드

라이브러리는 프로그램 개발 시 재사용 가능한 함수와 심볼들을 모아 컴파일해 둔 목적 파일들의 모음이다. 링킹 방식에 따라 정적 라이브러리와 동적 라이브러리로 구분된다.

### 정적 라이브러리 (Static Library)
- **특징**: 링킹 시 라이브러리의 기계어 코드가 실행 파일 내부에 직접 복사된다.
- **장점**: 실행 시 외부 의존성이 없어 배포가 간편하고 속도가 빠르다.
- **단점**: 실행 파일 크기가 커지며, 라이브러리가 수정되면 전체 프로젝트를 다시 빌드해야 한다.
- **생성 및 사용법**:
  C 표준에서 정적 라이브러리는 `lib` 접두사와 `.a` 확장자를 사용한다.
  ```bash
  # 1. 목적 파일 생성
  gcc -c mylib.c -o mylib.o

  # 2. ar 아카이브 도구로 정적 라이브러리 생성
  ar rcv libmylib.a mylib.o

  # 3. 아카이브 내 오브젝트 파일 목록 확인
  ar t libmylib.a

  # 4. 정적 라이브러리를 포함하여 빌드 (-l 플래그 사용 시 lib 접두사와 .a 제외한 이름 지정)
  gcc main.c -L. -lmylib -o out
  ```
  전체 정적 링킹을 강제하려면 `-static` 옵션을 추가한다.

### 동적 라이브러리 (Dynamic Library)
- **특징**: 실행 파일에 라이브러리 코드가 포함되지 않고, 프로그램 실행 시점에 OS 로더에 의해 메모리에 적재되어 공유된다 (`.so` 확장자).
- **장점**: 여러 프로세스가 메모리를 공유할 수 있어 메모리가 절약되고, 바이너리 크기가 작으며, 라이브러리 교체가 용이하다.
- **원리**: PLT(Procedure Linkage Table)와 GOT(Global Offset Table)를 통해 함수 실제 주소를 동적으로 바인딩한다.

### 동적 라이브러리 런타임 환경변수
리눅스에서 동적 라이브러리를 탐색하는 기본 경로 외에 사용자 정의 경로를 지정할 때 환경변수를 활용한다.

- `LD_PRELOAD`: 지정된 라이브러리를 다른 모든 라이브러리보다 최우선으로 로드한다.
  ```bash
  export LD_PRELOAD=$(realpath ./libmylib.so)
  ```
- `LD_LIBRARY_PATH`: 동적 링커가 공유 라이브러리를 탐색할 추가 디렉터리 경로를 콜론(`:`)으로 구분하여 설정한다.
  ```bash
  export LD_LIBRARY_PATH=$(realpath ./libs):$LD_LIBRARY_PATH
  ```

- **기본 라이브러리 검색 경로 확인**:
  ```bash
  ld --verbose | grep SEARCH_DIR | tr -s ' ;' '\n'
  ```

## GCC 핵심 명령어 옵션

- `-o <파일명>`: 생성할 출력 파일의 이름을 지정한다. 생략 시 기본값은 `a.out`이다.
- `-c`: 소스 코드를 컴파일 및 어셈블까지만 수행하여 오브젝트 파일(`.o`)을 생성한다.
- `-E`: 전처리 과정만 수행하여 결과를 화면 또는 지정된 파일(`.i`)로 출력한다.
- `-S`: 어셈블 단계까지만 수행하여 어셈블리 소스(`.s`)를 생성한다.
- `-g`: GDB 디버거로 소스 코드 라인을 추적하며 분석할 수 있도록 디버깅 심벌을 바이너리에 포함한다.
- `-Wall`: 일반적인 코드 잠재 결함 및 경고 메시지를 모두 출력한다 (Warning All).
- `-I<경로>`: 헤더 파일 인클루드 경로(`include path`)를 추가한다.
  - `-I.` 옵션으로 현재 디렉터리를 포함하면 `#include <my_header.h>` 형식으로 참조할 수 있다.
- `-L<경로>`: 링커가 라이브러리 파일(`.a`, `.so`)을 탐색할 디렉터리를 추가한다.
- `-l<이름>`: 링크할 라이브러리 이름을 명시한다 (예: `-lmylib` -> `libmylib.a` 또는 `libmylib.so` 링크).
