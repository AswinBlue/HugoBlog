## GDB 개요 및 디버깅 준비

GDB(GNU Debugger)는 리눅스 및 유닉스 계열 시스템에서 C/C++ 프로그램의 실행 흐름을 추적하고 메모리와 레지스터 상태를 분석하는 강력한 디버깅 도구이다.

효과적인 디버깅을 위해 다음의 4가지 실행 맥락(Context)을 파악하는 것이 핵심이다.
- **Register**: CPU 레지스터에 보관된 현재 연산 값
- **Disassembly**: 현재 명령어 포인터(RIP/EIP) 부근의 기계어 역어셈블 코드
- **Stack**: 현재 스택 프레임에 적재된 로컬 변수 및 반환 주소
- **Backtrace**: 현재 실행 지점에 도달하기까지 호출된 함수들의 호출 스택

> [!TIP]
> 보안 및 바이너리 분석 환경에서는 [pwndbg](https://github.com/pwndbg/pwndbg) 플러그인을 설치하면 레지스터, 스택, 역어셈블 화면이 컬러풀한 통합 컨텍스트로 자동 출력되어 디버깅 효율이 크게 향상된다.

### 컴파일 및 ELF 바이너리
- GCC 컴파일 시 `-g` 옵션을 반드시 포함해야 소스 코드 라인 정보 및 변수 심벌이 바이너리에 포함된다.
- 리눅스 실행 바이너리는 **ELF(Executable and Linkable Format)** 규격을 따르며, 헤더 및 기계어 코드가 담긴 섹션들로 구성된다.
- `readelf -h <파일명>` 명령어로 ELF 파일 헤더 정보를 열람할 수 있다.

### 코어 덤프 (Core Dump) 설정 및 분석
프로그램이 비정상 종료(Segmentation Fault 등)될 때 메모리 상태를 스냅샷으로 기록한 `core` 파일을 남기려면 사전 설정이 필요하다.

1. **코어 파일 크기 제한 해제**:
   ```bash
   ulimit -c unlimited
   ```
   `ulimit -a`로 `core file size` 설정을 확인할 수 있다.

2. **코어 덤프 생성 경로 및 패턴 확인**:
   ```bash
   cat /proc/sys/kernel/core_pattern
   ```
   기본 설정에 따라 현재 작업 디렉터리 또는 `/var/lib/apport/coredump/` 등에 `core` 파일이 생성된다.

3. **GDB로 코어 덤프 사후 분석 (Post-mortem Analysis)**:
   ```bash
   gdb <실행파일> <core파일>
   ```
   GDB가 비정상 종료 시점의 스택 프레임 위치로 즉시 진입하므로, `bt`(backtrace) 명령을 통해 충돌이 발생한 정확한 코드 라인을 즉시 추적할 수 있다.

### 실행 중인 프로세스 어태치 (Attach)
백그라운드에서 동작 중인 데몬 프로세스에 진입하여 실시간 디버깅을 수행할 수 있다.

```bash
gdb attach -p <PID>
```

환경변수 제어가 필요한 경우 GDB 내부에서 `set env LD_PRELOAD <경로>` 명령으로 라이브러리 참조 경로를 수정할 수 있다.

## 중단점(Breakpoint) 제어

- `b <라인>`: 특정 소스 코드 라인에 중단점 설정 (`break`와 동일)
- `b <함수명>`: 특정 함수 진입부에 중단점 설정
- `b <파일명>:<라인>`: 지정된 파일의 특정 라인에 중단점 설정 (예: `b test.cpp:25`)
- `b <라인> if <조건식>`: 특정 조건이 참일 때만 중단 (예: `break 25 if x == 0`)
- `b *<메모리주소>`: 특정 기계어 메모리 주소에 중단점 설정 (예: `b *0x401050`)
- `tb <위치>`: 일회성 임시 중단점(Temporary Breakpoint) 설정
- `w <변수>`: 하드웨어 워치포인트(Watchpoint)를 설정하여 해당 변수의 값이 변경될 때마다 자동 중단
- `i b`: 설정된 중단점 목록 확인 (`info breakpoints`)
- `d`: 모든 중단점 삭제 (`delete`)
- `d <번호>`: 특정 번호의 중단점 삭제
- `cl <라인/함수>`: 특정 라인 또는 함수의 중단점 제거 (`clear`)
- `disable <번호>` / `enable <번호>`: 중단점 임시 비활성화 및 재활성화
- `condition <번호> <조건>`: 기존 중단점에 조건식 부여
- `catch syscall <시스템콜>`: 특정 시스템 콜 호출 시 프로세스 정지

## 프로그램 실행 제어 명령어

- `r [인자1] [인자2]`: 지정된 인자와 함께 프로그램 실행 (`run`)
  - `start`: main 함수 시작 지점에 임시 중단점을 잡고 1회 멈춘 후 대기
  - `r <<< $(python3 -c "print('payload')")`: 표준 입력으로 쉘 명령 출력값 주입
- `c`: 다음 중단점을 만날 때까지 실행 계속 (`continue`)
- `n [숫자]`: 다음 소스 코드 라인으로 이동하되 함수 내부로 들어가지 않음 (`next`)
- `s [숫자]`: 다음 라인으로 이동하며 함수 호출문인 경우 내부로 진입 (`step`)
- `finish`: 현재 실행 중인 함수를 끝까지 수행하고 호출한 상위 함수로 복귀 (`fin`)
- `k`: 현재 실행 중인 프로그램 디버깅 강제 종료 (`kill`)
- `set <변수>=<값>`: 메모리 상의 특정 변수 값을 강제로 변조
- `set {int}0x123456 = 10`: 특정 메모리 주소에 직접 정수형 값 쓰기

## 상태 및 메모리 검사 명령어

### 변수 및 레지스터 확인
- `l [라인/함수]`: 소스 코드 목록 출력 (`list`)
- `info locals`: 현재 함수의 로컬 변수 목록 및 값 출력
- `info variables`: 전역 변수 목록 출력
- `info registers`: CPU 레지스터 전체 값 출력 (`i r`)
- `p <변수>`: 변수 또는 표현식 평가 및 출력 (`print`)
- `p/x <변수>`: 16진수로 변수 출력
- `p/t <변수>`: 2진수로 변수 출력
- `p/f <변수>`: 부동소수점 형식으로 출력
- `p *<배열>@<길이>`: 연속된 배열 원소 n개 일괄 출력
- `p *<구조체>`: 구조체 내부 전체 필드 출력

### 메모리 덤프 (x 명령어)
지정된 메모리 주소의 내용을 검사할 때 `x/<개수><포맷><단위크기> <주소>` 형식을 사용한다.
- 단위 크기: `b`(1바이트), `h`(2바이트), `w`(4바이트), `g`(8바이트)
- 출력 포맷: `x`(16진수), `d`(10진수), `u`(부호없는 10진수), `o`(8진수), `i`(기계어 어셈블리), `s`(문자열)
- 예시:
  - `x/4wx 0x7fffffffe000`: 해당 주소부터 4바이트씩 4개를 16진수로 출력
  - `x/10gx $rsp`: 스택 포인터 주소부터 8바이트 단위로 10개 출력
  - `x/5i $pc`: 프로그램 카운터(PC)의 다음 기계어 명령 5줄 역어셈블

### 스택 프레임 및 메모리 레이아웃
- `bt`: 프로그램의 함수 호출 백트레이스 출력 (`backtrace`)
- `f <인덱스>`: 호출 스택 프레임 중 특정 번호 프레임으로 포커스 전환 (`frame`)
- `display <변수>`: 명령어 실행 단계마다 지정된 변수 값을 지속적으로 자동 출력
- `undisplay <번호>`: 자동 디스플레이 해제
- `vmmap`: 프로세스의 가상 메모리 매핑 구조(코드 영역, 힙, 스택, 공유 라이브러리 주소) 확인

### TUI 모드 및 추가 명령어
- **TUI 모드 (Text User Interface)**:
  - `tui enable`: 상단에 소스 코드 또는 어셈블리 창, 하단에 GDB 프롬프트를 띄우는 텍스트 그래픽 모드를 활성화한다.
  - `tui disable`: TUI 모드를 종료하고 기본 쉘 프롬프트로 복귀한다.
  - `layout src` / `layout asm`: 소스 코드 또는 역어셈블리 창으로 레이아웃을 전환한다.
- `got` / `plt`: 공유 라이브러리 동적 링킹 테이블 상태 확인
- `q`: GDB 종료 (`quit`)
